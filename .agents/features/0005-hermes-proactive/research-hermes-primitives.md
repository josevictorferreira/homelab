# Hermes Agent v0.23.0 — proactive primitives inventory

**Version:** `hermes --version` → `Hermes Agent v0.23.0 (2026.9.24) · upstream 2bd378ed`. v0.23.0 (2026-11-05) is the newest GitHub release; the ~80 commits on `main` since then are fixes/CI/catalog only — nothing new for proactivity. The v0.23.0 release notes' relevant additions: `hermes cron cancel`, per-job `--catch-up on|off`, "prompts carry the fire time", `deliver: room:<id>@<profile>`, `/loop` live countdown.

## 1. Cron scheduler

**Schedule kinds** — exactly three: `cron`, `interval`, `once` (`/opt/hermes/cron/jobs.py:788-860` `parse_schedule`). Accepted string forms (also the `cronjob_manage` tool contract, `tools/cronjob_tools.py:1147`):
- `30m` / `every 2h` / `every hour` → `interval` (minutes)
- `in 30m` / `in 2h` → `once` (run_at = now+N)
- `every monday 9am`, `weekdays at 9am`, `every day at 9am` → `cron` expr (croniter)
- `0 9 * * *` (5–6 fields, named months/days OK) → `cron`
- ISO `2026-06-01T09:00:00` → `once` (naive = profile timezone; per-job `timezone` IANA override)

**Jitter / random windows: none.** Grepping `cron/*.py` and all docs for jitter/random/window/spread returns nothing. Only deterministic cron ranges (`0 9-17/2 * * 1-5`, used by the hydration blueprint). Confidence: high. Workarounds that *do* exist (see §Top primitives): a `$0` random pre-gate script, or the agent self-scheduling `in Nm` one-shots.

**Silent skip (yes, first-class):**
- `[SILENT]` — `cron/scheduler.py:539 SILENT_MARKER`, `:560 _is_cron_silence_response` accepts `[SILENT]`, bare `SILENT`, `NO_REPLY`, `NO REPLY` as the whole response or first/last line (not substring). The cron system prompt already instructs the model about it (`cron/scheduler_prompt.py:276-281`). Output is still saved to `cron/output/<job_id>/`, delivery row status `suppressed` (`cron/delivery_queue.py`). Failed runs always deliver. Docs: `user-guide/features/cron.md` "Silent suppression".
- `[CRON_FAILURE]` alone on first line → mark run failed (delivers a failure notice).
- `no_agent: true` + `script`: empty stdout sends nothing (watchdog pattern).
- `script` pre-check: last stdout line `{"wakeAgent": false}` skips the LLM entirely; `{"wakeAgent": true, "context": {...}}` injects context (cron.md "Skipping the agent entirely: wakeAgent").
- `monitor` (tool arg; stored as `monitor_script` / `monitor_url`, `cron/monitor.py`): runs the source each tick, sha256 of exact output; unchanged → silent `no_change` run with no LLM; changed → unified diff injected into the prompt. Incompatible with `no_agent`.

**`deliver` grammar** (`cron/scheduler_delivery.py:871` default `local`; cron.md "Delivery options"): `origin` (default from chats; resolved at *create time* to a concrete target when created inside a cron run), `local`, `all`, `<platform>` (home channel — Matrix: `MATRIX_HOME_ROOM` or `/sethome`), `platform:chat_id[:thread_id]`, `bot-chat[:profile]`, `room:<room_id>@<profile>`, comma combos (`origin,all`). Matrix targets: `matrix:!roomid:server` (a DM is just a room, so the DM room id works), `matrix:!room:server:$eventid` for a thread (`plugins/platforms/matrix/send_targets.py`), `@user:server` is parsed as an explicit target (`tools/send_message_targets.py:42`; whether the adapter opens a DM from a bare user id I could not confirm — medium-low). Extras: `failure_deliver` (same grammar; `local` silences failures), `attach_to_session: true` (continuable — on Matrix opens a thread per delivery and seeds it so a reply has the brief in context), `cron.mirror_delivery`, `cron.delivery.notify` (push flag, default true).

**Other job fields** (`tools/cronjob_tools.py:1131-1225`): `no_agent`, `catch_up` (true = run once on return, false = skip; defaults: recurring once, one-shots skip after 120 s grace), `grace_minutes` 0–1440 (cron exprs only), `repeat.times`, `skills[]`, `context_from[]` (other job's last output), `continuity` (own previous non-silent output), `enabled_toolsets[]`, `workdir`, `timezone`, `pinned` (model pin), `paused`. Global: `cron.catch_up_missed`, `cron.misfire_grace_minutes`, `cron.failure_nudge_threshold` (3), `agent.max_turns` applies to cron runs (`scheduler.py:2448`).

**Internals you asked about:** `admissions` = executions ledger (`cron/executions.py`; "Admission recovery": a run keeps its fire identity until output + delivery handoff are recorded; interrupted runs pause for operator review). `deliveries.db` = `cron/delivery_queue.py` (durable handoff from a worker outside the gateway cgroup to the live adapter; statuses pending/delivering/delivered/failed/unknown/suppressed; claimed-then-died = `unknown`, never retried). `dispatch_held.json` = `cron/dispatch_hold.py` (gateway drain hold; keeps a one-shot's 120 s grace across a restart). Also useful: per-job durable KV **notepad** (`cron/notepad.py`, `hermes cron notepad <job_id> set k v` via the terminal tool, 16 KB/value, prompt-injected each run) — ideal for "what I already told the user".

**Agent-created / rescheduled jobs:** tool `cronjob_manage` (actions create/list/update/remove/run/pause/resume/cancel). Available in gateway chats and CLI by default (`check_cronjob_requirements`, `cronjob_tools.py:~1228`). **Inside a cron run it is blocked unless `cron: allow_agent_scheduling: true`** (default false; cron.md "Agent-managed scheduling"). With it on, a run can create `in 2h` / ISO one-shots for itself, tune its own cadence, or remove itself and still deliver its final answer. Confidence: high.

## 2. Goals (`goals:`)
`/goal <text>` = Ralph-style judge loop (`hermes_cli/goals.py`, gateway `gateway/run_goals.py`): after each turn an auxiliary judge returns done/blocked/continue/wait; "continue" re-injects a continuation user message; `goals.max_turns` (default 20) auto-pauses. **Not a background planner**: it only runs between turns of the session the user set it in, and dies with `/new`. The one timer-ish part: wait barriers (`wait_for_seconds`, `wait_on_pid`, `wait_on_session`, cap 30 min) resume the loop on their own. Docs: `features/goals.md`, config §"Standing Goals". Confidence: high.

## 3. Heartbeat / idle / wakeup
- **`/heartbeat every <interval> <prompt>`** (alias `/hb`; `hermes_cli/heartbeat.py`, floor 60 s, poll 5 s; gateway driver `gateway/run_goals.py:204`, restore after restart `gateway/run_heartbeat_restore.py`). Fires as a plain user turn **in the same session** (full conversation context, prompt cache intact), idle-only, missed ticks coalesce, user messages win, one per session, survives restart, cleared by `/new`/reset. Gateway: a bare `NO_REPLY`/`[SILENT]` reply sends nothing, no typing indicator while it works (`gateway/turn_context.py:21`, `run_turn.py:2166`). Prompt template adds "do not invent work". Set only via the slash command in that chat (no agent tool, no CLI subcommand). Docs: `features/heartbeat.md`.
- **`/loop [interval] <prompt> [--times N] [--until <cond>]`** with alias **`/proactive`** (`hermes_cli/loops.py`; floor 30 s; gateway watcher every 15 s `run_goals.py:531`). Omit the interval → **self-paced**: 1 m floor, exponential backoff to 15 m while the reply digest is unchanged, snaps back on change. Stops on `LOOP_COMPLETE`, `--times`, `--until` judge, `loops.max_ticks` (100). Same-session, defers to an active `/goal`. Silence suppression is documented for heartbeat, not for loop (medium-low). Docs: `features/loops.md`.
- **No generic idle-tick/initiative/ambient engine.** Grep results: `pending_messages/` is only the shutdown spool for undelivered inbound messages (`gateway/shutdown_flush.py`); `agent.gateway_notify_interval` (180 s) = "still working" notices during a long turn; `gateway_auto_continue_freshness` (3600) = resume a turn interrupted by restart; `curator` = skill-library maintenance only; `auxiliary.background_review` = memory/skill self-improvement fork; `cron/suggestions.py` = consent-first job proposals (never auto-creates). None message the user unprompted.

## 4. Sending an unprompted message
- `send_message` helper exists (`tools/send_message_tool.py`) but is **deliberately not registered as a model tool** (comment at `:28-30`; confirmed in hooks.md: "`send_message` is intentionally not registered… reserved for CLI, cron, kanban, MCP delivery paths"). `ctx.dispatch_tool()` cannot reach it either.
- Paths that do send: cron delivery; **`hermes send` CLI** (`hermes_cli/send_cmd.py`, "pipe text to any configured platform") — callable by the agent through the `terminal` tool, with a dedupe guard when the target equals the job's own delivery target (`send_message_tool.py:476 cron_auto_delivery_duplicate_target`); webhook `deliver_only`; kanban notifier; opt-in MCP server. `react_to_message` *is* a registered tool.
- Target grammar: `platform:chat_id[:thread_id]`, bare platform = home channel; Matrix `!room:server`, `!room:server:$event`, `@user:server`.

## 5. Hooks / plugins
- **Gateway event hooks** (`~/.hermes/hooks/<name>/HOOK.yaml` + `handler.py`, `gateway/hooks.py`; per profile under multiplex): `gateway:startup`, `session:start|end|reset|compress`, `agent:start|step|end` (agent:end carries `response`), `reaction:added|removed` (Slack only), `command:*`. Handlers are arbitrary async Python and may call platform APIs directly (docs example "Telegram Alert on Long Tasks").
- **Plugin hooks** (`ctx.register_hook`): `pre/post_tool_call`, `pre/post_llm_call`, `pre_verify`, `on_session_start/end/finalize/reset/delete`, `post_compaction`, `agent_loop_stopped`, `subagent_start/stop`, `pre_gateway_dispatch`, `post_gateway_admission`, `gateway_platform_event` (Telegram/Discord reactions/edits/threads only), approval & human-input hooks, streaming observers, kanban observers (`features/hooks.md`, `developer-guide/observer-hooks.md`).
- **No "scheduled"/"periodic"/"on_idle" hook.** A plugin's `register(ctx)` or a `gateway:startup` handler can spawn its own thread/task (nothing prevents it), but there is no sanctioned API to inject a turn into a session. The sanctioned way to inject external events is a **platform adapter plugin** (`gateway/platforms/ADDING_A_PLATFORM.md`; e.g. the `homeassistant` and `ntfy` plugins) or the webhook platform. Confidence: high.

## 6. Webhooks / monitor scripts / external events
- Routes in `platforms.webhook.extra.routes` or dynamic `hermes webhook subscribe <name> --events … --prompt … --deliver matrix --deliver-chat-id '!room:server' [--deliver-only] [--cron-job <id>]` → `~/.hermes/webhook_subscriptions.json` (hot-reloaded, no restart). Route fields: `secret` (HMAC; GitLab token), `profile`, `prompt` template `{dot.notation}`/`{__raw__}`, `events`, `filters`, `script` (payload JSON on stdin; printing `[SILENT]`, empty, or `{"__hermes_ignore__": true}` drops the event), `deliver`/`deliver_extra.chat_id`, `deliver_only` (no LLM), **`cron_job`** (fire an existing job with the rendered prompt as transient per-run context — the job keeps its own prompt/skills/deliver), `coalesce` (debounce by key), `mirror_to_session`, `skills`, per-route toolsets. The `webhook-subscriptions` skill lets the agent create subscriptions itself via the terminal tool. Docs: `messaging/webhooks.md`.
- "Monitor script": the cron `monitor` (hash-diff of a script/URL) and `script` (`wakeAgent`) gates above — RSS/feeds/Loki queries/calendar ICS fit `monitor_url` or a gate script. Grafana/Loki alerts fit a webhook route with `cron_job` or `deliver: matrix:…`.
- **Home Assistant** is a catalog platform plugin (`hermes plugins install homeassistant`): WebSocket state-change events become inbound events; `deliver: homeassistant:<notify target>`; `HASS_HOME_CHANNEL`.

## 7. Memory grounding inside a cron run
`cron/scheduler.py:2480-2515 _construct_cron_agent`: `skip_memory=False` (MEMORY.md + USER.md are in the system prompt), `load_soul_identity=True` (SOUL.md), `skip_context_files=not workdir` (AGENTS.md only with `workdir`), `platform="cron"`, `skip_background_review=True`. The session store is opened so cron runs are persisted and `session_search` works (`scheduler.py:1853`). Tools: `session_search` (FTS5 over past conversations: `query` discovery / `session_id` read / `around_message_id` scroll; `tools/session_search_tool.py:665`), `memory` (MEMORY.md/USER.md writes), plus the active memory provider's own tools — hindsight is a catalog plugin here, so its recall hooks apply as to any AIAgent (medium confidence; not bundled in the image's `plugins/memory/`). Job-level: `continuity`, `context_from`, notepad KV, and the fire time in the prompt. Honcho (`features/honcho.md`) is the upstream user-modelling memory provider if you want deeper "who is this user" state.

## 8. Upstream "proactive/companion" naming
- `/proactive` is literally an alias of `/loop`.
- Matrix docs call cron/reminder output "proactive messages" to the home room.
- Blueprint catalog (`cron/blueprint_catalog.py`; docs `guides/automation-blueprints.md`, `reference/automation-blueprints-catalog.mdx`): morning-brief, evening-winddown, habit-checkin, **hydration-move nudge** (prompt: "Vary the wording each time so it doesn't feel robotic"), gratitude-journal, on-this-day, learn-daily, custom-reminder, workday-start, news/price/competitor watches with `[SILENT]`.
- `human_delay: {mode: natural|custom, min_ms, max_ms}` simulates human typing pace on messaging platforms (config §"Human Delay").
- No "companion"/"initiative" mode exists upstream.

## Top primitives for surprising, human-feeling outreach
1. **Frequent interval job + `$0` random gate + `[SILENT]` + notepad.** `cronjob_manage(create, schedule="every 20m", script="maybe-reach-out.sh", prompt=…, continuity=true, deliver="matrix:!dm:server")` where the script prints `{"wakeAgent": false}` with probability 1−p (and only inside a time window). Randomness costs no tokens; the LLM still gets a veto via `[SILENT]`; notepad/`continuity` stop repetition. Catch-up/`grace_minutes: 0` so it never catches up late.
2. **Agent self-scheduled one-shots.** In the Matrix conversation (allowed by default) or from a cron run (`cron.allow_agent_scheduling: true`), the model picks the moment: `cronjob_manage(create, schedule="in 3h17m", prompt="You said you'd try X — ask how it went", deliver="origin")`. `origin` is pinned to the DM at create time; the job can remove itself and still deliver.
3. **`/heartbeat every 2h <standing instruction>` set in the Matrix DM.** The only primitive that runs with the live conversation context and prompt cache, idle-only, silent on `NO_REPLY`, no typing indicator — most "grounded" outreach. Limits: one per session, user-set, dies on `/new`.
4. **Event triggers:** webhook routes/`hermes webhook subscribe` with `cron_job` (Home Assistant/Loki/GitHub/calendar), `monitor_url` on feeds, HA platform plugin — reacting to the world is what reads least like a clock.

Gaps to keep in mind: no jitter anywhere; no agent-callable `send_message` (use `hermes send` via terminal if you must); no plugin hook for periodic/idle work; `/loop` silence handling undocumented.
